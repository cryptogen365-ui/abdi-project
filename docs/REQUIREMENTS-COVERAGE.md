# ممیزی پوشش الزامات STRATIVA

این سند نسخه ۰.۳ را با ۱۱۳ بخش پرامپت اصلی مقایسه می‌کند. «عملیاتی» یعنی رابط، مدل داده و API پایه وجود دارد؛ «زیرساخت آماده» یعنی مدل عمومی و نقاط توسعه فراهم است؛ «فاز تخصصی» یعنی به کتابخانه یا سرویس تخصصی جداگانه نیاز دارد.

## عملیاتی در نسخه فعلی

- فارسی و RTL، طراحی واکنش‌گرا و داده نمونه فارسی (۲، ۸۵، ۸۶، ۱۰۲، ۱۰۳)
- سازمان، شرکت، سلسله‌مراتب واحدها و کارکنان (۵، ۶)
- چشم‌انداز، مأموریت، ارزش‌ها، اصول، اولویت‌ها و فرضیات (۷)
- تحلیل SWOT، PESTEL، پورتر، رقبا، بازار، مشتری و سناریو (۸)
- استراتژی، مضامین و اهداف آبشاری (۹)
- موتور تعریف چارچوب‌های BSC، OKR، OGSM، Hoshin، EFQM، CSF و سفارشی (۱۰)
- کارت امتیازی، منظرها، اهداف و وزن‌ها (۱۱)
- شناسنامه KPI، طبقه‌بندی، فرمول، هدف، مالک داده و منبع داده (۱۳ تا ۱۸)
- معماری و پروفایل فرآیند (۲۱ تا ۲۳)
- ریسک، کنترل داخلی و انطباق (۳۴ تا ۳۶)
- OKR شامل Objective، Key Result، چرخه، پیشرفت، اعتماد و Check-in (۳۷)
- ابتکار، پروژه، وظیفه، منبع، بودجه و تحقق منافع (۳۸ تا ۴۳)
- قابلیت، شایستگی، شکاف و برنامه آموزش؛ مدیریت تغییر (۴۴، ۴۵)
- ارزیابی EFQM و مدل‌های بلوغ با معیار، شواهد، یافته و اقدام (۴۶، ۴۷، ۸۹، ۹۱)
- حاکمیت، کمیته، جلسه، تصمیم و مصوبه (۴۸ تا ۵۰)
- سناریو، فرض راهبردی و What-if به‌صورت رکورد قابل مدیریت (۵۲ تا ۵۴)
- بهبود، علت ریشه‌ای، CAPA و بنچمارک (۶۰ تا ۶۳)
- منبع داده، تبدیل و تبار داده توصیفی (۷۲)
- API واقعی FastAPI/OpenAPI و PostgreSQL با Docker (۷۳ تا ۷۶، ۱۰۰، ۱۰۱)
- رابطهٔ چندبه‌چند قابل توسعه بین همه موجودیت‌ها و Audit Log (۷۷، ۸۳، ۱۰۴، ۱۰۷، ۱۱۰)
- ارتباط انتخابی KPI ← هدف ← استراتژی، KPI ← فرآیند، مالک KPI/فرآیند از کارکنان و Task ← کارمند/هدف/فرآیند
- طبقه‌بندی مستقل KPI/PI/RI/KRI از پیشرو/پسرو، اهداف دوره‌ای KPI، مدل وزن‌دهی و API محاسبه امتیاز وزنی
- معیارهای سالانه EFQM، نقشه استراتژی، CSF و درختواره سلسله‌مراتبی فرآیندها
- اسناد و شواهد متادیتایی (۷۹)
- جست‌وجو، فیلتر، وضعیت اتصال، خطا، خالی، بارگذاری و بازخورد موفقیت (۸۲، ۹۶)

## زیرساخت آماده؛ تکمیل تخصصی در ادامه

- اهداف دوره‌ای، اندازه‌گیری KPI، روش‌های امتیازدهی و اعتبارسنجی داده (۱۶، ۱۷، ۱۹)
- SIPOC، RACI، SLA، بلوغ، هزینه و سلامت فرآیند (۲۵ تا ۳۳)
- RAID، هشدار زودهنگام، Gap Analysis، Workflow و Notification (۵۱، ۵۶ تا ۵۸، ۷۸، ۸۰، ۸۱)
- داشبوردها، گزارش‌ها، بسته جلسات و خروجی Excel (۶۴، ۶۵، ۹۲)
- RBAC، احراز هویت، tenant واقعی از هویت کاربر، OAuth/OIDC/SSO/LDAP (۴، ۵، ۸۴، ۹۲)
- Versioning سطح دامنه، soft-delete و audit کامل مقادیر قبل/بعد (۷۶، ۸۳)

## نیازمند فاز تخصصی یا کتابخانه خارجی

- نقشه استراتژی تعاملی React Flow و گراف وابستگی (۱۲، ۵۵)
- BPMN 2.0 با bpmn-js و Process Mining (۲۴، ۱۰۹)
- اتصال واقعی SAP/Odoo/Oracle/Power BI و خطوط ETL (۱۸، ۲۰، ۷۲)
- پیش‌بینی، شبیه‌سازی کمی و What-if محاسباتی (۵۴، ۵۹)
- دستیارها و تحلیل‌های AI با تأیید انسانی (۶۶ تا ۷۱، ۹۵)
- Consulting Workspace، کتابخانه صنعت و سازنده قالب (۱۵، ۸۸، ۹۰)
- Digital Twin سازمانی و تحلیل شبکه پیشرفته (۹۵، ۱۰۸، ۱۱۰)

## نکته معماری

مدل عمومی `business_records` برای سرعت توسعه نسخه اولیه استفاده شده است، اما رابطه‌ها در جدول مستقل `entity_relationships` ذخیره می‌شوند. برای محصول سازمانی نهایی، موجودیت‌های پرتراکنش مانند KPI Measurement، Workflow، User/Role و Integration Job باید به جداول تخصصی و migrationهای Alembic منتقل شوند.
